> **Status (2026-10-25):** Phases 1–2 shipped, Phase 4 (editor) shipped,
> Phase 3 (rendering polish) partial, Phases 5–6 (audio, menus, content, polish)
> not started. See [§10 Implementation Phases](#10-implementation-phases) for

> + Catch2 + MCP, all shipped).

## Overview

Build a 2.5D platformer game on top of the Whiskers Engine. "2.5D" means **2D gameplay with 3D visuals** — side-scrolling movement and jumping rendered with 3D geometry, lighting, and depth layers. Think *Donkey Kong Country*, *New Super Mario Bros*, or *Rayman Legends*.

### Design Goals
- Fast, responsive platformer controls with tight game-feel
- Visually rich 3D-rendered environments with parallax depth
- Tilemap-based levels with an integrated level editor
- Modular ECS architecture supporting heterogeneous game objects
- Cross-platform (macOS, Linux, Windows)

## 1. Architecture Changes

### 1.1 Entity Component System Refactor

Replace the monolithic `Entity` struct with a true component-based system.

**Components** (plain data structs):

| Component | Fields | Purpose |
|-----------|--------|---------|
| `TransformComponent` | `position: vec3`, `rotation: vec3`, `scale: vec3` | Spatial data for all entities |
| `PhysicsComponent` | `velocity: vec2`, `acceleration: vec2`, `onGround: bool`, `gravityScale: float`, `mass: float` | Physics state |
| `ColliderComponent` | `shape: enum(AABB, Circle, Capsule, Tile)`, `bounds: ...`, `isTrigger: bool`, `layer: CollisionLayer` | Collision geometry |
| `RenderComponent` | `mesh: MeshRef`, `texture: TextureRef`, `material: MaterialRef`, `sortOrder: int`, `visible: bool` | Rendering data |
| `SpriteAnimComponent` | `frames: vector<TextureRef>`, `frameDuration: float`, `currentTime: float`, `loop: bool`, `playing: bool` | Sprite animation state |
| `HealthComponent` | `current: int`, `max: int`, `invincibleTimer: float` | Player/enemy health |
| `PlayerInputComponent` | `moveAxis: float`, `jumpHeld: bool`, `jumpPressed: bool`, `attackPressed: bool` | Input state |
| `CameraComponent` | `followTarget: EntityId`, `offset: vec2`, `smoothSpeed: float`, `bounds: Rect` | Camera configuration |
| `PlatformComponent` | `moveType: enum(Static, Moving, Falling, Conveyor)`, `path: vector<vec2>`, `speed: float` | Platform behavior |
| `EnemyAIComponent` | `state: enum(Patrol, Chase, Attack, Stunned)`, `patrolStart: float`, `patrolEnd: float`, `detectionRange: float` | Enemy behavior |

All 10 of the above are implemented in [`src/core/Component.h`](../src/core/Component.h).
The following gameplay-specific components also shipped and are not part of the
original plan — treat this spec as the baseline, not the full component set:

| Component (shipped, not in plan) | Purpose |
|---|---|
| `AttackComponent`, `ProjectileComponent` | Melee + fireball combat |
| `PickupComponent`, `LetterComponent`, `MessengerComponent`, `DeliveryZoneComponent`, `NPCComponent` | Parcel-delivery flow (see [`platformer-demo.md`](platformer-demo.md)) |
| `HazardComponent`, `ParticleComponent` | Damage sources + particle entities (no renderer yet) |
| `MagicorPlayerComponent`, `MagicorEnemyComponent`, `OrbComponent` | Second-game concept layered on the same ECS |

**Systems** (pure functions operating on component views):

| System | Reads | Writes | Phase |
|--------|-------|--------|-------|
| `InputSystem` | `PlayerInputComponent`, `TransformComponent` | `PlayerInputComponent` | Early Update |
| `MovementSystem` | `PlayerInputComponent`, `PhysicsComponent` | `PhysicsComponent` | Update |
| `PhysicsSystem` | `PhysicsComponent`, `ColliderComponent`, `TransformComponent` | `PhysicsComponent`, `TransformComponent` | Update |
| `CollisionSystem` | `ColliderComponent`, `TransformComponent` | `TransformComponent`, `PhysicsComponent` | Update |
| `AnimationSystem` | `SpriteAnimComponent` | `SpriteAnimComponent`, `RenderComponent` | Update |
| `CameraSystem` | `CameraComponent`, `TransformComponent` | Camera uniform state | Late Update |
| `RenderSystem` | `RenderComponent`, `TransformComponent` | Framebuffer | Render |
| `EnemyAISystem` | `EnemyAIComponent`, `TransformComponent`, `ColliderComponent` | `EnemyAIComponent`, `PhysicsComponent` | Update |

Shipped systems live in [`src/main_platformer.cpp`](../src/main_platformer.cpp) and
include the baseline above (as `PlatformerInputSystem`, `PlayerMovementSystem`,
`SpriteRenderSystem`, `ParallaxRenderSystem`, etc.) plus `HazardSystem`,
`CombatSystem`, `PickupSystem`, `DeliveryZoneSystem`, `LevelTransitionSystem`,
`NPCInteractionSystem`, `EnemyMovementSystem`, and `MovingPlatformSystem`.

### 1.2 Entity Manager Improvements

- Support **entity destruction** (currently missing)
- Support **component queries** ("give me all entities with PhysicsComponent + ColliderComponent")
- Use **sparse sets** or **archetype-based** storage for cache efficiency
- Entity IDs should be stable handles (generation counter pattern)

## 2. Physics System

### 2.1 Core Requirements

- **Gravity**: Configurable global gravity vector (default: `(0, -25.0)`)
- **Fixed timestep**: Physics updates at a fixed 120 Hz regardless of frame rate
- **Semi-fixed integration**: Verlet or semi-implicit Euler for stability

### 2.2 Collision Detection

- **Broad phase**: Spatial hash grid or sweep-and-prune
- **Narrow phase**: AABB-AABB, AABB-Circle, Circle-Circle resolution
- **Collision layers**: Bitmask-based layer system (Player, Enemy, Platform, Pickup, Projectile)
- **Trigger volumes**: Non-blocking colliders for events (level triggers, checkpoints)

### 2.3 Collision Response

- **Solid resolution**: Push entities out of overlap along minimum penetration axis
- **Ground detection**: Raycast or shape-cast downward to set `onGround` flag
- **One-way platforms**: Collide only when falling downward (optional from below)
- **Slopes**: Support sloped surfaces with configurable max climb angle (~45°)
- **Moving platforms**: Carry standing entities with platform velocity

### 2.4 Platformer-Specific Physics

- **Variable jump height**: Tap = short hop, hold = full jump
- **Coyote time**: ~100ms grace period after walking off edge where jump still works
- **Jump buffering**: ~100ms input buffer so pressing jump just before landing still fires
- **Air control**: Reduced horizontal control in air (~60% of ground control)
- **Fall speed cap**: Maximum terminal velocity

## 3. Rendering System

### 3.1 Projection

- **Hybrid approach**: Orthographic projection for gameplay plane (X-Y), perspective depth for parallax
- **Gameplay plane**: Z = 0 is the primary 2D plane where physics and collisions occur
- **Depth layers**: Background at Z < 0, foreground overlays at Z > 0
- **Ortho width**: Configurable (e.g., 20 world units visible horizontally)

### 3.2 Parallax Background System

- **3+ depth layers**: Sky (0.0x), far mountains (0.2x), mid trees/buildings (0.5x), near bushes (0.8x)
- Each layer is a textured quad or tile-strip
- Camera offset multiplied by parallax factor per layer
- Seamless horizontal tiling

### 3.3 3D Geometry Rendering

- **Platforms**: 3D box geometry with texture materials (not flat sprites)
- **Props**: 3D meshes for decorations (barrels, crates, signs)
- **Lighting**: Directional light + per-entity point lights for atmosphere
- **Shadows**: Simple shadow maps or projected shadow sprites under characters
- **Particles**: Particle system for dust, sparks, explosions, collectible sparkles

### 3.4 Animation System

- **Sprite sheets**: Grid-based or packed atlas textures
- **Animation definitions**: JSON-defined animations with frame indices and durations
- **Animation state machine**: States and transitions based on entity state
- **Blending**: Crossfade between animations (optional stretch goal)

### 3.5 Material System

- **PBR-lite**: Diffuse texture + normal map + specular (simplified)
- **Emissive**: Glow for pickups, power-ups, hazards
- **Alpha blending**: For transparent objects (water, glass, ghosts)

## 4. Camera System

### 4.1 Follow Camera

- Tracks a designated target entity (the player)
- **Configurable offset**: Position camera relative to player (e.g., slightly above and ahead)
- **Smooth interpolation**: Lerp toward target position each frame
- **Directional bias**: Show more space in the direction the player is facing

### 4.2 Camera Bounds

- Per-level rectangular bounds (camera cannot go outside)
- Support vertical scrolling levels and horizontal scrolling levels

### 4.3 Camera Effects (Stretch)

- **Screen shake**: On impacts, explosions
- **Slow zoom**: During cinematic moments
- **Dead zone**: Center region where player movement doesn't move camera

## 5. Level System

### 5.1 Level File Format

Levels are stored as **JSON** files for easy editing by the level editor and hand-editing.

```json
{
  "name": "Level 1 - Green Hills",
  "spawn": { "x": 2.0, "y": 3.0 },
  "bounds": { "left": 0, "right": 100, "bottom": -5, "top": 30 },
  "gravity": { "x": 0, "y": -25.0 },
  "parallax": {
    "layers": [
      { "texture": "sky.png", "depth": 0.0, "color": "#87CEEB" },
      { "texture": "clouds.png", "depth": 0.2 },
      { "texture": "hills_far.png", "depth": 0.5 },
      { "texture": "trees_near.png", "depth": 0.8 }
    ]
  },
  "tilemap": {
    "tileSize": 1.0,
    "columns": 100,
    "rows": 35,
    "tiles": [ ... ]
  },
  "entities": [
    {
      "type": "enemy_patrol",
      "position": { "x": 15.0, "y": 3.0 },
      "properties": { "patrolStart": 12.0, "patrolEnd": 22.0, "speed": 2.0 }
    },
    {
      "type": "collectible_coin",
      "position": { "x": 8.5, "y": 6.0 }
    }
  ],
  "music": "green_hills.ogg",
  "ambientParticles": [
    { "texture": "leaf.png", "spawnRate": 2.0, "velocity": { "x": -0.5, "y": -0.3 } }
  ]
}
```

### 5.2 Tilemap System

- **Grid-based**: Rectangular grid of tile references
- **Multi-layer**: Background tiles, collision tiles, foreground tiles
- **Tile properties**: Each tile defines collider type, is one-way, is hazard, etc.
- **Chunk loading**: For very large levels, load/unload chunks (stretch goal)

### 5.3 Tile Types

| Tile Property | Description |
|---------------|-------------|
| `solid` | Full collision block |
| `oneWay` | Collide only from above |
| `slopeUp` / `slopeDown` | Angled surface |
| `hazard` | Damages on contact (spikes, lava) |
| `decorative` | Visual only, no collision |
| `conveyor` | Applies horizontal force to standing entities |

## 6. Level Editor

### 6.1 Technology

- **Standalone mode**: Runs as a separate executable or as a mode toggle in the main engine
- **Uses the same renderer**: What-you-see-is-what-you-get (WYSIWYG)
- **ImGui overlay**: Dear ImGui for editor UI panels on top of the OpenGL render

### 6.2 Editor Features

#### 6.2.1 Tilemap Editing
- **Brush-based painting**: Click/drag to place tiles
- **Tile palette sidebar**: Scrollable grid of available tiles
- **Multi-layer editing**: Toggle visibility/editability per layer
- **Undo/Redo**: Full action history (minimum 100 steps)
- **Tile properties panel**: Edit collider type, slope angle, etc.

#### 6.2.2 Entity Placement
- **Entity palette**: Draggable entity templates (enemy, collectible, checkpoint, etc.)
- **Position editing**: Click to place, drag to move
- **Property inspector**: Edit entity-specific properties in sidebar
- **Selection & manipulation**: Click to select, drag to move, delete key to remove

#### 6.2.3 Level Properties
- **Level name**: Text field
- **Spawn point**: Visual marker, drag to reposition
- **Camera bounds**: Visual rectangle, draggable handles
- **Gravity**: X/Y numeric fields
- **Parallax layers**: Add/remove/reorder layers, assign textures, set depth factor

#### 6.2.4 Save/Load
- **Save to JSON**: Writes level file in the format specified in §5.1
- **Load from JSON**: Opens existing level files
- **Auto-save**: Periodic save to `.autosave` file
- **Level browser**: Thumbnail grid of all levels in the project

#### 6.2.5 Playtesting
- **Instant playtest**: Press button/hotkey to spawn at level's spawn point and play
- **Debug overlay**: Toggle physics debug view (colliders, velocities, ground state)
- **Entity debug**: Show entity names, properties, AI state on hover

### 6.3 Editor UI Layout

```
┌─────────────────────────────────────────────────────┐
│  File  Edit  View  Playtest  Help                   │  Menu bar
├──────────┬──────────────────────────────┬───────────┤
│          │                              │           │
│ Tile     │                              │ Entity    │
│ Palette  │       VIEWPORT               │ Palette   │
│          │   (OpenGL rendered scene)    │           │
│ [tile]   │                              │ [enemy]   │
│ [tile]   │                              │ [coin]    │
│ [tile]   │                              │ [spawn]   │
│          │                              │           │
├──────────┴──────────────────────────────┴───────────┤
│ Layers: [✓]BG [✓]Collision [✓]FG  │ Zoom: 100%     │
│ Status: Ready  │ Pos: (12.5, 3.0)  │ Undo: ● Redo:○│
└─────────────────────────────────────────────────────┘
```

## 7. Game Systems

### 7.1 Player Controller

- **States**: Idle, Run, Jump, Fall, Hurt, Dead
- **Movement**: Responsive ground movement with acceleration/deceleration curves
- **Jump**: Variable height, coyote time, jump buffering
- **Health**: 3+ health points with invincibility frames after hit
- **Animation**: State-driven sprite/3D animation

### 7.2 Enemy System

- **Patrol enemy**: Walks back and forth on a defined path, turns at edges/walls
- **Chase enemy**: Pursues player when in range
- **Hurt state**: Can be stunned/damaged by player action
- **Death**: Animation + optional particle effect + optional drop

### 7.3 Collectibles

- **Coins/gems**: Pickup for score
- **Health pickup**: Restore health
- **Power-ups**: Temporary abilities (speed boost, shield, double jump)
- **Checkpoint**: Respawn point on death

### 7.4 UI/HUD

- **In-game HUD**: Health bar, score, collectible count
- **Pause menu**: Resume, Restart, Quit
- **Title screen**: Game logo, Start, Settings
- **Game Over screen**: Score, Retry, Quit

### 7.5 Audio System

- **Library**: SDL2_mixer or miniaudio
- **Music**: Looping background tracks per level
- **SFX**: Jump, land, collect, hurt, enemy death, power-up
- **Volume controls**: Separate sliders for music and SFX

---

## 8. Input System

- **Buffered input**: Track pressed/released/this-frame state (not just held)
- **Gamepad support**: Left stick / D-pad for movement, face buttons for jump/attack
- **Keyboard**: WASD or arrow keys for movement, Space for jump, Shift for attack
- **Configurable keybindings**: Stored in a config file
- **Input dead zones**: Configurable analog stick dead zones

## 12. Open Questions

1. **Custom physics vs Box2D?** ✅ **Resolved: custom.** `PhysicsSystem` ships; Box2D never added. Revisit only if we need rotational dynamics or chained bodies.

2. **2D sprites on 3D geometry or full 3D characters?** ✅ **Resolved: 2D sprites + 3D environment.** `SpriteAnimator` + `SpriteRenderSystem` handle characters; tilemap/renderer produces 3D-feel environment.

3. **Dear ImGui or custom editor UI?** ✅ **Resolved: Dear ImGui** (v1.90.5 via FetchContent). Also used for the pixel-art sprite editor.

4. **JSON or binary level format?** ✅ **Resolved: JSON** via nlohmann/json. Editor serializes JSON; test fixtures use JSON. ⚠ **Follow-up:** the two shipped demo levels are still hard-coded in `main_platformer.cpp` and should be migrated to JSON.

5. **SDL2_mixer vs miniaudio?** ❌ **Still open.** No audio integrated. Recommendation stands: **miniaudio** — single header, no external deps.

### New open questions

6. **Where do the demo levels live?** Hard-coded C++ today; the editor exists but the game doesn't consume its output. Pick JSON-only or keep code-authored levels for the demo and gate the editor on a separate "custom levels" path.
7. **In-tree games vs. separate repos?** `platformer-demo.md` says games live in separate repos, but `games/astro-smash/` ships in-tree. Decide: is `games/` for *examples only*, or will the main demo stay here?
8. **Audio shape before implementing it:** Positional/pannable, or stereo-only? Needed to pick the miniaudio API surface.
9. **HUD technology:** Reuse Dear ImGui for in-game HUD (easy, slightly off-aesthetic) or build a lightweight textured-quad UI layer (more work, better looking)?
